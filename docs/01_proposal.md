## 1. 프로젝트 개요

### 1.1 프로젝트 정의
- **프로젝트명**: Biz Risk Predictor (biz-risk-predictor)
- **한 줄 소개**: 서울시 행정동 × 업종 단위로 **다음 분기 폐업 위험도**를 예측하고, 그 이유를 **SHAP**으로 설명하는 웹 서비스
- **핵심 타깃**: 예비 창업자, 기존 자영업자, 상권 분석가
- **분석 범위**: **서울특별시 25개 자치구 · 약 420여 개 행정동** (서울 열린데이터광장에서 실제로 확보 가능한 데이터만 사용)
- **핵심 기능**
  1. 자치구 → 행정동, 업종(외식업/서비스업/소매업 → 세부 업종)을 선택
  2. 다음 분기 폐업 위험 확률과 3단계 등급(안정/보통/위험) 표시
  3. SHAP 폭포형 그래프로 위험도를 **높인 요인과 낮춘 요인**을 시각화
  4. 위험도를 높인 상위 요인을 바탕으로 맞춤형 진단 문장과 대응 가이드 제공
  5. 선택한 업종에서 위험도가 높은 행정동 Top 10

### 1.2 추진 배경
소상공인의 창업 후 3년 내 폐업률은 여전히 높습니다. 그런데 기존 상권 분석 서비스는 점포 수나 매출 같은 통계를 보여주는 데서 그쳐, 자영업자가 직접 대책을 세우기 어렵습니다. 이 프로젝트는 머신러닝 예측 결과에 더해 **"왜 그런 위험도가 나왔는지"** 를 설명 가능한 인공지능(XAI)으로 풀어, 실제로 행동할 수 있는 인사이트를 주는 것을 목표로 합니다.

## 2. 문제 정의 (분류, Classification)

| 항목 | 내용 |
| --- | --- |
| 분석 단위 | 분기 × 행정동 × 서비스업종 |
| 입력 X | **t분기**의 상권 지표 17개 (점포, 매출, 유동인구, 업종 대분류) |
| 타깃 y | **t+1분기** 폐업률이 같은 업종 대분류 안에서 상위 30%에 들면 1(고위험), 아니면 0 |
| 유형 | 이진 분류 → 확률을 3구간으로 나눠 표시 (안정 < 0.35 ≤ 보통 < 0.6 ≤ 위험) |

> **데이터 누수 방지**: v1의 예시 코드는 *같은 분기* 폐업률(`close_rate`)로 레이블을 만들면서 그 값을 피처로도 넣었습니다. 이렇게 하면 모델은 정답을 그대로 보고 맞히는 셈이라 정확도가 100%에 가깝게 나와도 의미가 없습니다. v2에서는 **"이번 분기 정보로 다음 분기 폐업 위험을 예측"** 하도록 시간 축을 분리했습니다.

## 3. 강의 핵심 개념 연계 (Course Alignment)

| 강의 | 개념 | 프로젝트 적용 위치 |
| --- | --- | --- |
| OT | ML 3대 유형 중 **분류** | 고위험(1) / 정상(0) 이진 분류 |
| 1-3 NumPy | 배열 Shape·dtype 검증 | `X.shape == (n_samples, 17)`, `y.ndim == 1`, `assert X.shape[0] == y.shape[0]`, `astype(float64)` (`ml/pipeline/train.py`) |
| 1-4 Pandas | 결측치, `loc/iloc`, `groupby` | `isna().sum()` → `groupby(['quarter','industry_code']).transform(fillna(median))`, 행정동·업종별 집계와 전분기 대비 증감률 (`preprocess.py`) |
| 4장 결정 트리 | 지니 불순도, 과적합 제어 | `criterion="gini"`, `max_depth / min_samples_split / min_samples_leaf` 튜닝 |
| 4장 앙상블 | 랜덤 포레스트, 병렬 처리 | `RandomForestClassifier(n_estimators=200, n_jobs=-1)` |
| 4장 모델 선택 | 교차검증, 그리드 서치 | `GridSearchCV(cv=StratifiedKFold(5), scoring="roc_auc")` |
| 4장 XAI | TreeSHAP | `shap.TreeExplainer`, `예측값 = 기준값 + ΣSHAP` 성립을 코드로 검증 (`explain.py`) |
| 4장 피처 중요도 | 불순도 중요도의 한계 | `feature_importances_`와 평균 \|SHAP\| 비교 그래프 |

- 확장 후보 (같은 사이트에서 확보 가능): 상권변화지표-행정동(OA-15575), 상주인구-행정동(OA-22183), 직장인구-행정동(OA-22184), 집객시설-행정동(OA-22169)

### 4.1 피처 설계 (17개)

| 구분 | 피처 |
| --- | --- |
| 점포 | 점포 수, 유사업종 점포 수, 프랜차이즈 비율, 개업률, 현재 분기 폐업률, 점포 수 증감률(QoQ) |
| 매출 | 분기 매출액, 점포당 매출액, 매출 증감률(QoQ), 주말 매출 비중, 매출 데이터 제공 여부 (37개 업종은 매출 미제공) |
| 유동인구 | 유동인구, 점포당 유동인구(과밀도), 주말 유동인구 비중 |
| 업종 | 외식업 / 서비스업 / 소매업 원-핫 |

### 4.2 전처리 원칙
- 점포 수 **5개 미만** 조합은 제외합니다. 점포가 2곳뿐이면 1곳만 폐업해도 폐업률이 50%가 되는 식의 노이즈를 막기 위해서입니다.
- 결측치는 **같은 분기·업종의 중앙값**으로 대체하고, 그래도 남으면 전체 중앙값으로 채웁니다.
- 레이블 기준(70분위수)은 **학습 구간에서만** 계산하고, 업종 대분류별로 따로 정합니다. 외식업처럼 원래 폐업률이 높은 업종 때문에 생기는 편향을 막기 위해서입니다.

## 5. 모델링 및 평가

- **분할**: 시간 기준 분할입니다. 마지막 4개 분기를 테스트셋으로 써서, 미래 데이터로 학습하는 일을 막습니다.
- **모델**: 결정 트리(베이스라인)와 랜덤 포레스트(메인)
- **튜닝**: `GridSearchCV` 5-fold, 평가 기준 ROC-AUC, `class_weight`(None / balanced)도 함께 탐색
- **평가지표**: Accuracy, Precision, Recall, F1, ROC-AUC, 혼동행렬
- **해석**: TreeSHAP의 전역 해석(beeswarm, bar)과 개별 상권 해석(waterfall)

## 6. 시스템 아키텍처 및 기술 스택

```
[Browser] ──▶ Next.js 16 (Vercel)
                ├─ 페이지: 대시보드 / 진단 결과 (Tailwind CSS, Recharts)
                └─ Route Handler(/api/*) ──▶ FastAPI ML 서버
                                               ├─ RandomForest (joblib)
                                               └─ shap.TreeExplainer
[ml/pipeline] 수집 → 전처리 → 학습 → 해석 ──▶ artifacts(model, meta, latest)
```

| 영역 | 기술 | 선택 이유 |
| --- | --- | --- |
| Frontend | Next.js 16 (App Router), TypeScript, Tailwind CSS 4, Recharts 3 | Streamlit보다 UI 자유도와 반응형 구현이 뛰어나고, Route Handler로 ML 서버를 감출 수 있음 |
| ML API | FastAPI, scikit-learn, SHAP | 파이썬 ML 생태계를 그대로 쓰고 자동 API 문서(/docs)를 제공 |
| 데이터 처리 | Pandas, NumPy, PyArrow | 강의 실습과 같은 도구 |

> **v2 변경**: 로그인과 검색 이력은 핵심 가치(예측 + 설명)와 관련이 적어 **Supabase(DB/Auth)를 제외**했습니다. 상태를 저장하지 않는 구조라 배포와 운영이 단순해집니다.
