# 데이터셋 확보 가이드

> 서울 열린데이터광장에서 **인증키를 발급받고**, 이 프로젝트에 필요한 상권분석 데이터 3종을 수집하는 전 과정입니다.
> 조회 일자: 2026-10-08. 사이트가 개편되면 메뉴 이름이 조금 다를 수 있습니다.

| # | 데이터셋 (데이터 ID) | Open API 서비스명 | 갱신 | 규모(조회 시점) | 단위 |
| --- | --- | --- | --- | --- | --- |
| 1 | [서울시 상권분석서비스(점포-행정동)](https://data.seoul.go.kr/dataList/OA-22172/S/1/datasetView.do) (OA-22172) | `VwsmAdstrdStorW` | 분기 | 약 77.5만 행 | 분기 × 행정동 × 서비스업종 |
| 2 | [서울시 상권분석서비스(추정매출-행정동)](https://data.seoul.go.kr/dataList/OA-22175/S/1/datasetView.do) (OA-22175) | `VwsmAdstrdSelngW` | 분기 | 약 37.6만 행 | 분기 × 행정동 × 서비스업종 |
| 3 | [서울시 상권분석서비스(길단위인구-행정동)](https://data.seoul.go.kr/dataList/OA-22178/S/1/datasetView.do) (OA-22178) | `VwsmAdstrdFlpopW` | 분기 | 약 9,350행 | 분기 × 행정동 |

- 제공 기관: 서울신용보증재단 (서울시 상권분석서비스 [golmok.seoul.go.kr](https://golmok.seoul.go.kr))
- 제공 기간: 2026-07-03부터 **2021년 이후 자료만** 제공합니다. (2026-10-08 수집 기준 **2021Q1 ~ 2026Q2, 22개 분기**, 425개 행정동, 100개 업종)
- ⚠️ 100개 업종 중 **37개는 추정매출 데이터가 전혀 없습니다** (변호사·세무사 사무소, 독서실, 주유소 등). 매출 행 수가 점포보다 적은 이유입니다.
- 공통 키: `STDR_YYQU_CD`(기준 년분기, 예: `20241`), `ADSTRD_CD`(행정동 코드 8자리), `SVC_INDUTY_CD`(서비스업종 코드, 예: `CS100001`)

### 1.1 실제 응답 예시 (sample 키로 확인)

```json
// VwsmAdstrdStorW (점포-행정동)
{"STDR_YYQU_CD":"20241","ADSTRD_CD":"11110515","ADSTRD_CD_NM":"청운효자동",
 "SVC_INDUTY_CD":"CS100003","SVC_INDUTY_CD_NM":"일식음식점",
 "SIMILR_INDUTY_STOR_CO":19.0,"STOR_CO":18.0,"FRC_STOR_CO":1.0,
 "OPBIZ_RT":11.0,"OPBIZ_STOR_CO":2.0,"CLSBIZ_RT":11.0,"CLSBIZ_STOR_CO":2.0}
```

| 컬럼 | 의미 | 사용처 |
| --- | --- | --- |
| `STOR_CO` / `SIMILR_INDUTY_STOR_CO` | 점포 수 / 유사업종 점포 수 | 피처, 과밀도 계산 |
| `FRC_STOR_CO` | 프랜차이즈 점포 수 | 프랜차이즈 비율 |
| `OPBIZ_RT` / `CLSBIZ_RT` | 개업률 / 폐업률(%) | 피처, **다음 분기 폐업률 → 레이블** |
| `THSMON_SELNG_AMT` | 당월(분기) 매출 금액 | 매출, 점포당 매출, 증감률 |
| `WKEND_SELNG_AMT` | 주말 매출 금액 | 주말 매출 비중 |
| `TOT_FLPOP_CO`, `MON_FLPOP_CO` … `SUN_FLPOP_CO` | 총·요일별 유동인구 | 유동인구, 점포당 유동인구, 주말 비중 |

## 2. 인증키 발급 (단계별)

### Step 1. 서울시 통합회원 가입
1. [서울 열린데이터광장](https://data.seoul.go.kr) 오른쪽 위의 **회원가입**을 누릅니다.
   서울시 통합회원 가입 페이지(seoul.go.kr)로 이동합니다.
2. 약관에 동의하고, 화면 안내에 따라 본인 확인을 거친 뒤 아이디와 비밀번호를 만듭니다.
   > 열린데이터광장은 서울시 통합회원 계정(SSO)으로 로그인합니다. 서울시 홈페이지 계정이 이미 있다면 그 계정을 그대로 쓰면 됩니다.

### Step 2. 일반 인증키 신청
1. 열린데이터광장에 **로그인**합니다.
2. 상단 메뉴 **이용안내 → Open API 소개**로 이동합니다. ([바로가기](https://data.seoul.go.kr/together/guide/useGuide.do))
3. **`일반 인증키 신청`** 버튼을 누릅니다.
   > ⚠️ `실시간 지하철 인증키 신청`이 아닙니다. 상권분석 데이터는 **일반 인증키**로 조회합니다.
4. 신청서를 작성합니다. 아래 입력 예시를 참고하세요.

| 항목 | 입력 예시 |
| --- | --- |
| 서비스(사용) 환경 | 웹사이트 개발 |
| 사용 URL | `http://localhost:3000` (배포 후에는 실제 도메인이나 GitHub 저장소 URL) |
| 관리용 대표 이메일 | 본인 이메일 (학교 메일 권장) |
| 활용 용도 | 교육 / 학술 (선택지에서 가장 가까운 항목) |
| 내용 | 건국대학교 「데이터사이언스활용」 수업 개인 프로젝트. 서울시 상권분석서비스(점포·추정매출·길단위인구, 행정동) 데이터를 활용해 행정동·업종별 다음 분기 폐업 위험도를 예측하고 SHAP으로 원인을 설명하는 웹 서비스 개발 |

5. 약관에 동의하고 신청을 완료합니다.

### Step 3. 발급된 키 확인
- 로그인한 상태에서 **마이페이지 → 인증키 관리(인증키 신청 내역)** 에서 발급된 키를 확인합니다.
- 키는 32자리 정도의 영문·숫자 문자열입니다.

### Step 4. 키 동작 테스트
브라우저 주소창이나 터미널에서 아래처럼 1~5건만 조회해 봅니다. `{KEY}` 자리에 발급받은 키를 넣으세요.

```bash
curl "http://openapi.seoul.go.kr:8088/{KEY}/json/VwsmAdstrdStorW/1/5/"
```

- 응답에 `"CODE":"INFO-000","MESSAGE":"정상 처리되었습니다"`가 있으면 성공입니다.
- `INFO-100`(인증키 오류)이 나오면 키를 잘못 복사했거나 아직 활성화되지 않은 것입니다.
- 키 없이 구조만 확인하려면 `{KEY}` 자리에 `sample`을 넣으면 됩니다. 이 경우 1~5건만 조회됩니다.

### Step 5. 프로젝트에 키 등록

```bash
cd ml
cp .env.example .env
# .env 파일을 열어서 SEOUL_API_KEY=발급받은키 입력
```

> 🔒 `.env`는 `.gitignore`에 포함되어 있습니다. **인증키를 코드나 GitHub에 직접 올리지 마세요.** 배포 환경에서는 플랫폼의 환경변수 설정을 사용합니다.

### 이용 제약
- Open API는 **한 번에 최대 1,000건**까지 요청할 수 있습니다. 수집 스크립트가 1,000건씩 나눠서 자동으로 호출합니다.
- 열린데이터광장 안내에 따르면, **활용사례(갤러리)** 에 인증키와 함께 결과물을 등록하면 이용 제약 없이 계속 쓸 수 있습니다. 배포 후 등록하면 포트폴리오 실적으로도 남길 수 있습니다.

## 3. 데이터 수집

```bash
cd ml
source ../.venv/bin/activate

python -m pipeline.collect --sample        # 키 없이 3개 API의 응답 구조 확인 (각 5건)
python -m pipeline.collect                 # 전체 수집 → data/raw/{stores,sales,flpop}.csv
python -m pipeline.collect --only flpop    # 일부만 다시 수집
```

- 점포 데이터가 약 77만 건이라 API를 약 1,160번 호출합니다. 네트워크 상황에 따라 **수십 분**이 걸릴 수 있습니다.
- 실데이터를 수집하면 `data/raw/MOCK_DATA.txt`(임시 데이터 표시 파일)가 자동으로 삭제됩니다.

### 대안: CSV 파일 직접 내려받기
각 데이터셋 페이지(위 표의 링크)에서 CSV 파일을 받을 수도 있습니다. 다만 CSV는 **한글 컬럼명**(예: `기준_년분기_코드`, `점포_수`)을 쓰기 때문에, 이 프로젝트의 전처리 코드(영문 API 컬럼 기준)에 넣으려면 컬럼명 매핑이 필요합니다. **API 수집을 권장합니다.**

## 4. 임시(가상) 데이터 — 인증키 발급 전 개발용

```bash
cd ml
python -m pipeline.make_mock   # data/raw에 API와 같은 컬럼 구조의 가상 데이터 생성
```

| 항목 | 내용 |
| --- | --- |
| 목적 | 인증키 발급과 실데이터 수집 전에도 전처리 → 학습 → SHAP → API → 웹 전체 흐름을 개발하고 시연하기 위함 |
| 규모 | 25개 자치구 × 가상 행정동 6개 × 20개 업종 × 18개 분기(2021Q1~2025Q2) |
| 실제와 같은 점 | 컬럼명, 코드 체계(자치구 코드는 실제 값), 매출 결측 등 데이터 구조 |
| 실제와 다른 점 | 행정동 이름은 `노원3동(가상)`처럼 가상, 업종 코드는 예시, **폐업률은 임의 규칙으로 생성** |
| 표시 | `data/raw/MOCK_DATA.txt`가 있으면 전처리 시 경고 문구 출력 |

> ⚠️ 임시 데이터로 얻은 성능 수치와 SHAP 해석은 **파이프라인이 정상 동작하는지 확인하는 용도**일 뿐, 실제 서울 상권에 대한 결론이 아닙니다. 발표 때도 "임시 데이터 기준"이라고 반드시 밝힙니다.

## 5. 전체 파이프라인 실행 순서

```bash
cd ml
python -m pipeline.collect      # (또는 make_mock)
python -m pipeline.preprocess   # → data/processed/dataset.parquet, latest.parquet
python -m pipeline.train        # → ml/artifacts/model.joblib, meta.json, latest.parquet
python -m pipeline.explain      # → ml/artifacts/figures/*.png
```
